## 一、产品定位

一个**给自己用**的第三方皮肤管理器。皮肤全部由本人制作（「第三方」＝非 Hana 官方）。

它同时是两样东西：

1. **控制面板**——皮肤在哪、长什么样、怎么切、怎么退
2. **补丁执行器**——官方接口给不了的三层，由 Hana Agent 代劳贴入

> ⚠️ 措辞校正（已向用户说明）：agent 补的是**效果**，不是**接口**。宿主没开的入口谁都改不了，只能绕过（改安装目录里的主题文件）。

---

## 二、皮肤的定义

**一套皮肤 = 一个包 = 一个主题。** 包含四层：

| 层 | 内容 | 由谁提供 |
|---|---|---|
| 配色 | 61 个官方变量 | 每个皮肤自带 |
| 背景图 | 立绘 + 遮罩参数（亮度/暗度/模糊） | 每个皮肤自带 |
| 材质 | 毛玻璃、描边、overlay 强度 | **一份通用，所有皮肤共享** |
| 取景框动效 | canvas 动画 | **每个皮肤可选自己的**（也可复用通用版） |

### 材质通用化的改造前提

实测 `material/bold.css`：91 处 `var()`、16 处写死 hex、选择器绑死 `[data-theme="hana-moonlit-court"]`。

要改成通用层，需两件事：

1. 选择器 → `[data-theme^="hana-"]`（属性选择器，特异性等价）
2. 16 处写死色 → `var(--…)`

**尚未实测**，属"应该可以"级别。

## 三、功能清单

### 3.1 管理

- 安装 / 卸载 / 切换 / 启用停用
- **多个皮肤并存**，可选择性启用其中几个（不启用的不占注册表）
- 搜索
- 分组 / 标签
- 收藏置顶
- **每个皮肤存一张真实效果截图**（列表里显示截图，不是抽象色块）
- 导入时自动去重

### 3.2 制作（工作台）

- 改 61 个配色变量，实时预览
- 选背景图；**App 内可处理**：裁剪、调暗、压缩
- 调毛玻璃/材质参数
- 选或上传动效（允许直接带 `.js`）
- 导出成皮肤包，拖回来即可安装
- **同时支持手写 CSS 导入**（走另一条口子）

### 3.3 升级与容错

- Hana 升级导致补丁失效时：**App 主动提示**
- 提示后：**agent 自动重贴**（用户只负责重启）
- 回滚：**整套一键回滚**（用补丁自带的 backups/manifest 机制）

### 3.4 明确不做

- **不保留 custom 配色版**。衣橱不再往 `hana.themes.custom` 里塞东西；
  四个层全在补丁里，补丁主题自带的合成 CSS 已含配色。
- 不做分发给他人（只自己用）。

## 四、「够用了」的判据（两个场景都要达成）

1. 能把 hana-skin 和 Luna 都装进来、随时切换、坏了能退回去，**不用碰命令行**
2. 做一个新皮肤，从配色到背景到动效，**全在 App 里完成**，导出后能直接装

---

## 五、技术边界（已实测）

| 能力 | 官方 App API | 结论 |
|---|---|---|
| 配色（61 变量） | `hana.themes.custom.*` | 可做，但本项目**不用**（见 3.4） |
| 立绘背景图 | 无 `url()` 入口 | 只能打补丁 |
| 毛玻璃 / 材质描边 | 需组件级 CSS | 只能打补丁 |
| 浮层取景框动画 | 需执行 JS | 只能打补丁 |

补丁的固有代价：

- 装/更新皮肤 → 重启一次
- 已在注册表里的主题之间切换 → 即时，不重启
- Hana 每次升级 → 补丁失效，需重贴
